Harness 工程底座

从模型能力到可靠系统：为什么模型输出只是「提议」，Harness 怎么把提议变成受约束、可验证、可追踪的行动。运行时、工具、记忆、编排、安全与评估的一体化方法。

01

学习目标与阅读路径

目标1
能说出 Harness 的定位：模型输出是「提议」，底座负责适配、约束、验证、跟踪和恢复
目标2
能复述能力公式「可交付能力 = 模型能力 × 工具可用性 × 执行可靠性 × 治理覆盖率」并解释乘法含义
目标3
能区分权限与沙箱、临时性/永久性/未知性错误、控制/执行/数据三平面
目标4
能指出至少 2 个容易误解的地方（如「上下文越长越好」「只看最终成功率」）
目标5
能提出 1 个后续追问（比如：我们现有工具的接口离「好接口」标准差什么）
02

零基础背景包

背景补充 Harness（工程底座）

英文原词 harness 本义是「马具/挽具」，在 AI 工程里指包裹在模型外面、约束和驱动它干活的整套工程系统：运行时、工具接入、权限、日志等。圈内保留原词，译作「工程底座」。

为什么现在需要知道：本章主角就是它。

背景补充 Agent（智能体）

能多轮「观察—行动」、调用工具、持续执行任务的 AI 程序。与一次性问答的区别：它可能修改真实系统，要对端到端结果负责。

为什么现在需要知道：Harness 就是为 Agent 运行过程设计的约束层。

背景补充 幂等性（Idempotent）

同一操作执行一次和执行多次效果相同。比如「设置状态为 X」是幂等的，「创建一条记录」不是——重复执行会创建多条。

为什么现在需要知道：重试安全的前提是幂等键。它不是本文的主张，只是帮助你读懂原文。

背景补充 提示注入（Prompt Injection）

攻击者在输入或外部数据里藏入指令，诱导模型执行违背原意的行为。间接注入常藏在网页、文档等模型读取的内容里。

为什么现在需要知道：它是 Harness 威胁模型的第一类攻击面。

背景补充 可观测性（Observability）

通过指标（Metrics）、日志（Logs）、链路追踪（Traces）三种数据，回答「系统为什么这样运行」。不只是记最终答案。

为什么现在需要知道：它是贯穿 Harness 全程的横切保障之一。

05

核心判断与依据

判断1：模型输出只是「提议」

核心判断：模型或 Agent 的输出不能直接当行动执行；Harness 负责把它转换成受约束、可验证、可追踪的行动。

原文依据（第1页课程主线）：「模型或 Agent 输出只是‘提议’；Harness 负责把提议转换成受约束、可验证、可追踪的行动。」

判断 为什么重要：这是全篇的纲领，输出治理、门控、审批全部由此展开。误读：把模型回答直接当最终结果。

判断2：可交付能力是乘法，任一项近零整体显著下降

核心判断：可交付能力 = 模型能力 × 工具可用性 × 执行可靠性 × 治理覆盖率。模型决定能力上限，工程系统决定能力能否以可接受的风险和成本落地。

原文依据（第4页）：「可交付能力 = 模型能力 × 工具可用性 × 执行可靠性 × 治理覆盖率。任何一项接近零，整体能力都会显著下降。」

判断 为什么重要：短板决定成败，优化方向看最弱一项。误读：只升级模型就能交付。

判断3：系统设计的重点是让每一步更可控，不是让模型更敢做

核心判断：Agent 化放大能力也同步放大风险（错误变真实操作、偏差级联扩散、成本持续增长）；设计的重点是用确定性约束和证据维持边界。

原文依据（第2页）：「系统设计的重点，不是让模型‘更敢做’，而是让每一步都更可控。」（第8页）：「面对非确定性决策，系统要用确定性的约束和证据维持边界。」

判断 为什么重要：给「要不要放开自主权」提供准绳。误读：自主性越高系统越先进。

判断4：权限回答「是否允许」，沙箱回答「即使出错最多影响什么」

核心判断：权限与沙箱是两道不同的防线；加上「不要只靠黑名单」，构成纵深防御：入口规范化→风险分级最小权限→护栏审批→隔离执行→审计撤销。

原文依据（第27页）：「权限回答‘是否允许’，沙箱回答‘即使出错，最多能影响什么’。」「命令和编码变体难以穷举；白名单、结构化参数、沙箱和审计必须共同存在。」

判断 为什么重要：安全设计的基础分野。误读：有了权限检查就不需要沙箱。

判断5：长任务的主要风险是持续偏离，错误分类优先于重试次数

核心判断：长任务的主要风险不是一次失败，而是持续偏离目标却仍在消耗资源；重试前先分类：临时性退避重试、永久性修正升级、未知性隔离人工复核。

原文依据（第11页）：「长任务的主要风险不是一次失败，而是持续偏离目标却仍在消耗资源。」「错误分类优先于重试次数。」

判断 为什么重要：盲重试会放大副作用和成本。误读：失败就重试三次。

判断6：模型输出是候选结果，任一关键门控失败一票否决

核心判断：输出要过格式、能力、业务、安全、事实五层门控；任一关键门控失败即阻止副作用，返回可修正错误；纠正优于沉默。

原文依据（第17页）：「模型输出首先是候选结果，只有通过解析、验证和授权后才能成为系统行动。」「任一关键门控失败即阻止副作用，返回可修正错误。」「纠正优于沉默。」

判断 为什么重要：把「提议→行动」的闸门标准化。误读：格式对就行。

判断7：更长的上下文不等于更好的上下文

核心判断：优先级、相关性和证据密度比长度更重要；上下文分固定保护区（安全策略、当前目标、完成条件）和动态竞争区（可压缩淘汰），压缩要保留决定、约束、错误经验和来源指针。

原文依据（第15页）：「更长的上下文不等于更好的上下文；优先级、相关性和证据密度更重要。」

判断 为什么重要：上下文是成本也是噪音源。误读：窗口大就尽量多塞。

判断8：只看最终成功率会掩盖低效轨迹和危险中间行为

核心判断：评估要分步骤级（工具选择/参数正确率）、轨迹级（重复率、恢复质量、关键检查点）、任务级（目标达成、成本、安全事件）三层。

原文依据（第28页）：「只看最终成功率，会掩盖低效轨迹、高成本和危险的中间行为。」

判断 为什么重要：评估层决定改进方向。误读：成功率达标就万事大吉。

06

关键概念拆解

Harness（工程底座）

作者用法：位于模型与执行环境之间，承担适配、约束、验证、跟踪和恢复；不替代模型的领域推理、工具内部实现和业务流程规则。

「该做什么」由应用和模型决定 ｜ 「能否做、如何安全地做、做完怎样证明」由底座负责 原文依据（第3页边界判断）。

不要误解成：又一个中间件框架——它的核心职能是治理与执行协调。

三平面（控制 / 执行 / 数据）

作者用法：控制平面放策略、权限、配置、审批（决定怎么运行）；执行平面放任务循环、工具调用、重试（真正执行动作）；数据平面放会话、记忆、日志、审计（保存事实与证据）。观测结果反哺控制策略。

原文依据（第6页）：「按变化速度和责任拆分系统，比按代码目录拆分更稳定。」「分层的目的……让关键策略能够独立变化、独立测试、独立回滚。」

不要误解成：多拆几层组件——原文反例是「权限规则写死在工具代码中、状态只在进程内存里」这类耦合。

运行循环（Runtime Loop）

作者用法：有预算、有出口、有检查点的状态机：observe → decide → validate → act → record → checkpoint；每轮必须回答目标、预算、新事实、继续还是暂停。

原文依据（第9页）：「运行时不是一个无限循环，而是一台有预算、有出口、有检查点的状态机。」

不要误解成：while true 死循环调模型。

工具抽象与执行流水线

作者用法：工具接口是能力说明+安全合同+观测边界；执行走六步流水线：发现→授权→校验→执行→处理→记录；早失败原则——前置门控失败立即停止。

好接口 = 清晰名称 + 严格 Schema + 有界副作用 + 可操作错误 + 完整追踪 原文依据（第12/13页）。

不要误解成：接口只要功能对就行——危险信号包括「自由文本参数直接进入命令」「成功返回缺少可验证证据」。

多层记忆

作者用法：工作记忆（当前轮、高频小容量）、短期记忆（会话摘要）、长期记忆（稳定事实、持久可治理）；写入要有复用价值、可记录来源、可回滚；凭据和未验证猜测不写入。

记忆条目 = 内容 + 来源 + 时间 + 类型 + 置信度 + 权限 + 版本 原文依据（第14页）。

不要误解成：完整保存一切对话——记忆是「在正确时间提供足够且可信的信息」。

风险评估公式

作者用法：风险 = 可达性 × 影响范围 × 可逆性 × 发现难度；不只看「会不会发生」。低=只读可撤销，中=有限写入可补偿，高=外部发布、删除、转账、权限变更。

原文依据（第26页）。

不要误解成：概率低=风险低——不可逆的高影响操作即使罕见也是高风险。

误解与边界

误解1：Harness 会限制模型能力，是负担

为什么容易误解：约束看起来在「拦着」AI。原文真正说了：模型决定能力上限，工程系统决定能力能否以可接受的风险和成本落地；约束优先、可验证、渐进信任让能力可交付。原文没说：约束越多越好。避免方法：按「先定义禁止项和审批点，再扩展能力」的顺序做。

误解2：上下文窗口越大，效果越好

为什么容易误解：长窗口是新模型卖点。原文说：更长的上下文不等于更好的上下文；优先级、相关性和证据密度更重要；动态区内容该压缩就压缩。避免方法：按固定保护区+动态竞争区组织上下文。

误解3：失败就重试，多试几次总能成

为什么容易误解：重试是分布式系统常用手段。原文说：错误分类优先于重试次数；永久性错误盲重试无效，未知性错误要隔离人工复核；重试必须配合幂等键。避免方法：先分类，再选低/中/高风险对应策略。

误解4：上了 MCP 等标准协议，安全和信任问题自动解决

为什么容易误解：协议名字里有「标准」。原文说：标准协议降低集成成本，但不会自动解决授权、可信度和故障隔离；权限结果慎缓存，缓存命中也要保留审计信息。避免方法：接入前查 Schema 兼容、凭据隔离和降级方案。

误解5：多 Agent 比单 Agent 强，加上就行

为什么容易误解：人多力量大的直觉。原文说：多 Agent 的价值来自并行专业化，而不是简单增加模型调用次数；要警惕协作放大器——同一错误被多个角色复述、通信 Token 超过实际工作量。避免方法：委派要写清合同（子目标+输入工件+允许工具+验收标准+截止条件）。

• 模型输出只是提议；Harness 把提议转换成受约束、可验证、可追踪的行动。
